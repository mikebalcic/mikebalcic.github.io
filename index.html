关于

我是 mikebalcic。我的日常是看配置：一份 YAML 从 staging 跑到 production 到底改了哪些项。 `diff` 给的是行，`confdiff` 给的是"哪个配置项变了"——这两件事之间的距离，就是我想填的空。 我把差异分成新增、删除、改动、空白四类，因为最后那类通常只是有人跑了格式化， 不该和真正的行为变更混在一起讲。我关心输出的可读性，因为这些结果常常要贴进 PR 描述给人看。

  • 用键路径说话：`db.pool.size` 比「第 42 行」有用得多。
  • 格式变化单列一类，不和真实变更混在一起。
  • 工具的解析范围刻意做窄，但会在 README 里说清楚窄在哪。
  • 输出要能直接贴进 PR 描述，不要求读者二次加工。
